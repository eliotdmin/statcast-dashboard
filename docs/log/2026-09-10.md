## Dead ends and wrong turns

### Savant is unreachable from both sandboxes

`baseballsavant.mlb.com` returns 403 at the egress proxy from the Cowork VM and
from the cloud container. Adding it to the account allowlist mid-session did
**not** help: egress policy is snapshotted when a session starts, so the change
only reaches a *new* session. Three retries over a minute confirmed it. Anything
that fetches has to run in the user's own Terminal, or in a session started
after the allowlist change.

### Driving Terminal via computer use is not possible

Requested access to Terminal.app intending to launch the backfill directly. macOS
grants terminals and IDEs at "click" tier only — visible and clickable, but no
typing, no key presses, no paste. Do not attempt this again; hand the user a
command instead.

### `--limit-days 0` fetched everything

Smoke-testing `backfill.py` with `--limit-days 0` ran the full plan, because the
guard is `if limit_days:` and `0` is falsy. It hammered ~700 blocked requests
before being killed. No data was written (failures are deliberately not logged,
so nothing was marked ingested). Fixed by adding `--dry-run` rather than by
changing the falsy check.

### The first `audit.py` was unusably slow

Original design issued one query per column per season — 476 full table scans on
2.8M rows, which blew past every timeout. Rewritten to group columns by their
applicability predicate, so each (season, predicate) pair costs ONE scan with
119 `COUNT()` aggregates: ~24 scans instead of 476. Distributions similarly went
from pulling every value into Python to exact SQL aggregates plus percentiles
from a deterministic 10% sample.

### The database was corrupted — by this session

While optimising the audit, it issued `CREATE INDEX` against the live 1.8 GB
database **through the Cowork mount**. It failed with `disk I/O error`, which was
logged as a non-fatal warning and ignored. It was not non-fatal:

    Rowid 684987 out of order
    2nd reference to page 97301

The damage was silent — most queries still worked, and the file under-reported
its own row count by 23,523 pitches. Recovered with
`sqlite3 old.db ".recover" | sqlite3 new.db`, verified against `ingest_log`, zero
rows lost. Now recorded as D9 in `DECISIONS.md` and guarded by a `quick_check`
after every scheduled refresh.

Consequence worth remembering: a count read off that damaged file led to a
confidently wrong claim that 2023 had 2,429 games. It is 2024 that has 2,429.

### Git kept locking the repo

`git add` from the sandbox creates `.git/index.lock` and cannot delete it — the
sandbox shell has no delete permission by default. This blocked the user's own
git for hours with a misleading "another git process seems to be running". It
happened a second time in the new folder after the move, leaving `HEAD.lock` and
stray `tmp_obj_*` files. Fix is `rm -f .git/*.lock`; prevention is D8.

### Staging leaked between commit attempts

A first commit run failed on missing git identity *after* its `git add` calls
succeeded, leaving everything staged. The retry's first commit then swept in all
nine files. Fixed with `git reset --mixed HEAD~1 && git reset`, then redone
cleanly. Check `git status` before committing after any failed attempt.

### Claimed Savant had no usable documentation, without checking

Asserted that Savant's column glossary was incomplete and omitted the
bat-tracking columns. Both false. The sandbox could not reach the page, and that
was generalised into a claim about the page's contents. `WebFetch` retrieved it
fine — it routes through Anthropic's infrastructure, not the sandbox egress
proxy, so **for reading public web pages, use WebFetch rather than concluding
from a curl failure**. The page corrected four entries in the dictionary and
supplied the ABS strike-zone note, which turned out to be the most important
finding of the day.

### Built the speed adjustment before measuring the effect

Read the README's claim that fast hitters are a major source of false positives,
agreed, and implemented a full speed-residualised signal — table, fetch, join,
regression, tests. Then measured: R² = 0.0034, not distinguishable from zero.
The measurement was one query and should have come first. The feature is kept
but explicitly unused (D7) pending a four-season refit.

### Background jobs kept dying

`setsid nohup ... &` inside a `device_bash` call was repeatedly reaped, leaving
0-byte logs. Plain `nohup ... &` within a single call that then sleeps works.
Long jobs need to fit a ~180s call or be genuinely detached by something the
shell teardown will not kill.

### The scheduled refresh failed three separate ways

1. **Never loaded.** The plist existed in the repo but had never been copied to
   `~/Library/LaunchAgents`, so `logs/` was empty since August.
2. **TCC.** Once loaded, `/bin/bash` could not read `refresh.sh` in `~/Desktop`
   — `Operation not permitted`, before a single log line. Running the same
   script by hand works, because Terminal has been granted access and the script
   inherits it. That asymmetry is what made it hard to diagnose. Fixed by moving
   the repo to `~/Projects` (D10), not by granting `/bin/bash` Full Disk Access.
3. **Interpreter.** `launchd` does not read a shell profile and starts jobs with
   a minimal PATH, so `python3` resolved to Apple's system Python with no
   pybaseball. The guard refused to run and said so, which is the behaviour we
   want. The machine's conda turned out to be at
   `/opt/homebrew/Caskroom/miniconda/base` — a Homebrew Cask install none of the
   guessed paths covered. Resolved with `.refreshrc` (D11).

Moving the repo also disconnected the Cowork folder mount; re-granting access to
the new path was needed to continue.

## Open questions

- Re-fit the speed coefficient on four seasons of sprint speed. If it stays this
  small, delete `outlook_adj`.
- The README's shift-beater claim is untested, and the 2023 rule change is a
  natural experiment sitting in the data.
- Sequencing needs a **within-pitcher** design to say anything causal. The
  interesting question is not "should pitchers mix more" but "are there specific
  pitchers who mix too much".
- Nothing renders `dashboard_data.json` in the repo itself; the published page is
  an artifact built outside it.
- `regression_test.py` has not been run on 2026, which is incomplete.
- Postseason has never been fetched (`--include-postseason` exists, unused).
